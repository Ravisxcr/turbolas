# Permissive Parsing & Dirty Data Recovery

Historical well logs collected over decades by different operators and logging trucks frequently violate official CWLS standards. Standard parsers often fail or crash when encountering malformed headers, missing delimiters, or corrupted tokens.

TurboLAS provides an industrial-grade **Permissive Validation Mode** designed to parse legacy well files with maximum resilience.

---

## 1. Enabling Permissive Mode

Pass `mode=ValidationMode.PERMISSIVE` to `turbolas.read()`:

```python
from turbolas import ValidationMode
import turbolas

well = turbolas.read("malformed_legacy_well.las", mode=ValidationMode.PERMISSIVE)
```

---

## 2. Supported Heuristics & Repairs

### 1. Missing Dot in Mnemonics
The CWLS specification requires a period `.` separating the mnemonic from the unit (e.g. `STRT.M`). Many legacy files omit the dot entirely:
```text
~WELL INFORMATION
WELL ACME #1 : WELL NAME
COMP TEXACO : COMPANY
```
**TurboLAS Repair**: In permissive mode, TurboLAS takes the first whitespace-separated token as the mnemonic and parses the remainder into value and description fields.

### 2. Missing Colons
Lines that omit the `:` delimiter before descriptions:
```text
~CURVE INFORMATION
DEPT.M Depth curve
GR  .GAPI Gamma ray
```
**TurboLAS Repair**: Parses the line using whitespace heuristics, assigning the trailing tokens to the description.

### 3. Non-Standard Comments & Comment Characters
Files that use C-style, SQL-style, or Fortran-style comments:
```text
// Generated by Logging Unit 4
-- Calibration run 12
! Run date 1994-08-12
```
**TurboLAS Repair**: Recognizes `//`, `--`, and `!` as comments and strips them without error.

### 4. Spaces Around Section Delimiters
Section lines with non-standard whitespace after the tilde `~`:
```text
~ WELL INFORMATION
~  CURVE INFORMATION
```
**TurboLAS Repair**: Strips whitespace around `~` and classifies the section header correctly.

### 5. Non-Standard / Custom Sections
Files containing vendor-specific proprietary sections:
```text
~P_CALCULATED_CURVES
~Z_CUSTOM_METRICS
```
**TurboLAS Repair**: In strict mode, unknown sections raise an error. In permissive mode, they are classified as `SectionType.Other` and preserved in `well.other_lines`.

### 6. Corrupt / Asterisk Data Tokens
Logging equipment often records asterisks or error abbreviations for saturated or uncalibrated tools:
```text
1000.0   45.2   ***    ERR
1000.5   52.1   ****   BAD
1001.0   48.9   ND     #N/A
```
**TurboLAS Repair**: Automatically treats `***`, `****`, `*****`, `ERR`, `ERROR`, `BAD`, `OFF`, `EMPTY`, `ND`, `N.D.`, `INF`, `#N/A`, `-`, and `?` as `NaN`.

### 7. Duplicate Curve Mnemonics
Files with multiple curves sharing identical mnemonics (e.g., raw and processed curves both named `GR`):
**TurboLAS Repair**: Uniquely indexes duplicate names using suffixed keys (`GR`, `GR_2`, `GR_3`) so all curves remain accessible.

### 8. Curve Names on `~A` Delimiter Line
Some legacy formats list curve mnemonics directly after `~A`:
```text
~A DEPT GR NPHI RHOB
1000.0 45.2 0.15 2.45
```
**TurboLAS Repair**: Extracts the curve names from the delimiter line if the `~C` section was omitted.
